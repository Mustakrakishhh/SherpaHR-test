# API существующего приложения

Ответ: `{"data": ...}`; ошибка: `{"error": "описание"}` с соответствующим
HTTP-статусом. JSON UTF-8. Заголовок `X-Demo-User: 1` выбирает Анну,
`2` — Бориса, `3` — Веру. По умолчанию 1. Это открытый демо-переключатель,
не доказательство личности; локальный API не предназначен для публикации в сеть.

| Метод и путь | Текущее поведение |
|---|---|
| `GET /api/health` | Проверка запуска сервиса |
| `GET /api/context` | Демо-пользователи, выбранный пользователь, время UTC и дата создания демо |
| `GET /api/projects` | Только проекты текущего пользователя, участники и количество задач |
| `GET /api/attention` | Снимок всех незавершённых задач активных проектов, которыми руководит пользователь и в которых он состоит |
| `GET /api/projects/{id}/tasks` | Все задачи доступного проекта |
| `POST /api/projects/{id}/tasks` | Создать задачу в активном проекте |
| `GET /api/tasks/{id}` | Доступная задача с комментариями и авторами |
| `PATCH /api/tasks/{id}` | Изменить поля с проверкой версии |
| `POST /api/tasks/{id}/comments` | Сохранить комментарий, вернуть его с автором и временем, HTTP 201 |
| `PATCH /api/tasks/{id}/comments/{commentId}/attention` | Руководителю: обработать или вернуть просьбу, HTTP 200 |

Поля задачи для создания и изменения: `title`, `description`, `status`,
`assignee_id`, `due_at`. При создании `title` обязателен. Неизвестные поля
отклоняются. Исполнитель — участник проекта или `null`. Даты — строго
`YYYY-MM-DDTHH:mm:ssZ` либо `null`; текущий UI редактирует их с точностью до минуты.
Для PATCH обязательно целое поле `version`, полученное при чтении.
Успешное изменение увеличивает версию; устаревшая версия возвращает 409.
Метод добавления комментария принимает `{"body":"текст","help_requested":true}`.
Поле `help_requested` необязательно, по умолчанию `false`; допускается только
JSON boolean. Это явная просьба руководителю, не зависящая от ключевых слов.
Для завершённой задачи `help_requested:true` отклоняется с 409 без вставки
комментария. Сначала нужно явно переоткрыть задачу. Обычные комментарии
(`help_requested:false` или отсутствие поля) доступны и в готовых задачах.
Краевые пробелы
обрезаются; пустой текст, превышение лимита и неизвестные поля отклоняются (422).
Автор берётся из выбранного демо-пользователя, время — с сервера в UTC.
Комментарий не меняет версию полей задачи; архив и проверки членства сохраняются.
Объект комментария дополнен полями `help_requested`, `matched_phrase`, `is_request`,
`handled`, `handled_at`, `handled_by`, `handled_by_name`, `attention_version`.
Чтение всей переписки доступно через карточку задачи.

Изменение отметки: `PATCH .../attention` с `{"handled":true,"version":0}`.
`false` возвращает просьбу в обзор. Нужны членство и роль руководителя данного
проекта (иначе 403); для чужой задачи/несоответствующего комментария — 404,
для архива — 409. Обычный комментарий без просьбы не обрабатывается (422).
Версия берётся из `attention_version` комментария; устаревшая версия — 409.
Успешная операция увеличивает только эту версию. Автор/время обработки назначаются
сервером; при возвращении текущая отметка обработки очищается. Текст/автор/дата
самого комментария и версия полей задачи не меняются. Это текущее состояние
обращения, а не отдельный журнал аудита всех переключений.
Снятие отметки обработки в готовой задаче не меняет её статус и не возвращает её
в обзор; UI поясняет необходимость явного переоткрытия задачи.

Обзор возвращает `data: {generated_at, tasks}`. Каждая задача дополнена
`project_name`, `reasons`, `comment_count`, `last_comment` (объект комментария или
`null`), `discussion_signal` (`{comment, matched_phrase, explicit}` либо `null`),
`open_request_count` (число необработанных обращений). Причины:
`blocked`, `overdue`, `unassigned`, `discussion`; они могут сочетаться.
`overdue` означает `due_at < generated_at`. Готовые задачи и архив исключены.
`discussion` — хотя бы одна необработанная явная просьба либо возможная просьба
по словарю. Источник — последний по ID необработанный подходящий комментарий из
всей переписки; остальные обращения видны в карточке. Обработка одной просьбы
не скрывает остальные и не убирает другие причины внимания задачи.
Словарь и ограничения: [solution.md](solution.md).

Сортировка — срок по возрастанию (без срока в конце), затем ID. Причины не влияют
на порядок. API отдаёт все незавершённые задачи для двух режимов UI; фильтр причин
и поиск выполняются на клиенте. Поиск включает название, описание, проект и
последний комментарий, но не всю переписку. Снимок обновляется при открытии обзора,
вручную и после собственных изменений; фонового обновления нет.

Максимумы строк в байтах UTF-8: название 200, описание 10000, комментарий 5000.
Максимум тела изменения — 32 KiB. Ошибка валидации — 422, JSON — 400,
неизвестный пользователь — 401, отсутствующий или недоступный объект — 404,
запись в архив — 409. Поиск и фильтр статуса в текущем UI выполняются локально.
