# Проверки двух дефектов финального ревью

Это воспроизводимый ручной чек-лист браузерных проверок, не автоматический
frontend-тест. API-проверки включены в `php backend/tests/smoke.php` (96 проверок).
Для проверок используйте отдельную временную БД либо отдельный демо-экземпляр.

## Ошибка в полноэкранной карточке

1. При ширине окна 800 px выбрать Анну и открыть задачу #7 из обзора.
2. Ввести 101 кириллическую букву в название (202 байта, серверный лимит 200),
   изменить описание, набрать черновик комментария и поставить флажок помощи.
3. Сохранить задачу. Ожидание: ошибка в карточке видна поверх остальных элементов,
   фокус на её блоке; поля, комментарий и флажок сохранились. На сервере задача
   не изменилась. Основная страница не показывает дубликат ошибки под карточкой.
4. Ввести комментарий из 1800 символов «界» (5400 байтов при лимите 5000)
   и отправить из нижней части карточки. Ожидание: ошибка прокручивается в видимую
   область, весь текст и флажок остаются, комментарий не вставлен.
5. Восстановить обычный размер окна. Не использовать эти невалидные черновики
   для последующих проверок — открыть задачу заново.

## Запрос помощи в готовой задаче

1. В активной задаче #1 с существующей просьбой набрать обычный комментарий,
   поставить флажок помощи, выбрать статус «Готово» и сохранить задачу.
2. Ожидание: после успешного сохранения флажок снят и отключён; комментарий остался.
   Под формой пояснение: обычный комментарий доступен, помощь требует переоткрытия.
3. Отправить обычный комментарий. Ожидание: он сохраняется с автором, задача done.
4. Обработать прежнюю просьбу. Кнопка теперь «Снять отметку обработки», рядом
   объясняется, что готовая задача не входит в обзор.
5. Снять отметку. Ожидание: сообщение о необходимости переоткрытия, статус done
   не изменён, задача не добавлена в обзор. Автоматического изменения статуса нет.
6. Явно переоткрыть и сохранить задачу. Ожидание: необработанная просьба появляется
   в обзоре; это также проверяется автоматическим smoke-тестом.

API-регрессия отдельно проверяет 409 и отсутствие вставки при `help_requested:true`
для готовой задачи, включая запрос из устаревшей вкладки; обычный комментарий,
отметки старых просьб и версии продолжают работать. Права и архив не меняются.
